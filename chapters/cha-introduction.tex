As Thomas Ball stated:
\begin{quote}
    ``Software is intangible, having no physical shape or size.''~\citebibliography{Ball1996a}
\end{quote}

Unlike concrete objects, software has no shape that can be directly perceived. This raises a fundamental question: \emph{how can we represent something that has no physical form?} Software visualization addresses this question by mapping abstract software entities and relationships onto visual representations, making them easier to explore and understand.


\section{Context and Motivation}
\label{sec:intro_motivation}
Program comprehension is as old as software engineering itself. As software systems evolve and continuously grow in complexity, developers spend a significant portion of their time reading, navigating, and mentally reconstructing code structures rather than writing new features. Building and maintaining a mental model of a large codebase is a cognitive burden that affects daily software engineering tasks. An early study highlighted that program comprehension involves building an internal representation of the software by combining existing programming and domain knowledge with information obtained from source code and related documentation~\citebibliography{Von1995a}. This process is not necessarily linear: developers may start from high-level goals and previous knowledge and move towards specific implementation details, or instead build their understanding bottom-up by gradually grouping low-level code structures into higher-level concepts. During this process, they continuously formulate hypotheses about the purpose and behavior of program components, check them against the available information, and update their mental model as their understanding improves.

Despite decades of improvements in integrated development environments (IDEs), new programming paradigms, and new programming languages, the amount of time developers spend trying to understand source code has remained surprisingly stable for over thirty years~\citebibliography{Sieg2016a}. As Siegmund observes, research on program comprehension went through a period of limited activity before becoming more active again in recent years. Modern research not only confirms the central role of program comprehension in software engineering, but also provides stronger empirical and physiological evidence of these cognitive processes. By using measurement techniques such as eye-tracking, electroencephalography (EEG), and functional magnetic resonance imaging (fMRI), recent studies directly measure the cognitive load associated with code understanding. These studies show that reading source code involves both language-processing and higher-level cognitive areas of the brain.

Empirical measurements in development environments highlight the practical impact of this cognitive overload. Investigating developers' work habits, LaToza \etal~\citebibliography{LaTo2006a} revealed that developers invest massive effort into creating and maintaining mental models of software systems, which remain most unrecorded in formal documentation. Their study identified understanding the rationale behind existing code (such as understanding design decisions, historical changes, or temporary workarounds) as the most critical problem, reported as an issue by 66\% of surveyed developers. When documentation is insufficient or code exploration is not enough, developers often turn to face-to-face discussions with their colleagues to recover missing information, causing costly task switches and interruptions for their coworkers.

Quantifying this effort directly within the IDE, Minelli \etal~\citebibliography{Min2015a} provided empirical evidence showing that program comprehension takes up most of a developer's time. By recording more than 5 million low-level UI events during nearly 200 hours of development in Pharo, they found that program comprehension absorbs roughly 70\% of a developer's time. In comparison, active code editing takes only 5\%, while navigation accounts for about 4\%. Their study also identified another important source of cognitive load: developers spend nearly 14\% of their time interacting with and rearranging the IDE's user interface.

To address this problem, visual modeling languages (\eg UML~\citebibliography{Andr2005a}) and software visualizations~\citebibliography{Agou2022a,Wett2007a,Kuhn2010a} have been studied over the past decades. By presenting software structure and relationships visually, these approaches can help developers explore and understand complex systems without relying only on the source code.

\section{Problem Statement}
\label{sec-intro:problem_statement}
However, applying software visualization to real-world, large-scale systems introduces two fundamental and interconnected challenges:

\begin{itemize}
    \item \textbf{The Layout Problem:} Given a set of software entities, one must decide how to position them meaningfully on a canvas. Different layouts can highlight different structural or semantic aspects of the software, such as inheritance relationships, package structure, or coupling. A poor layout can hide important patterns and make the overall structure of the system harder to understand.

    \item \textbf{The Connectivity Problem:} While displaying relationships (\eg inheritance, method calls, and dependencies) enrich the information about how the system is connected, large software graphs can become extremely dense. As the number of entities increases, the number of connections can grow rapidly, leading to visual clutter, numerous edge crossings, and incomprehensible representations.
\end{itemize}

\section{Proposed Approach}
In this thesis, we explore a novel approach designed to tackle both problems. The approach is implemented in \wassis, a prototype developed in Pharo that combines Multidimensional Scaling (MDS) for class placement with Wave Function Collapse (WFC) for path generation.

First, we use Multidimensional Scaling (MDS)~\citebibliography{Torg1952a,Doug1998a}, a dimensionality reduction technique, to establish the placement of software entities on the canvas according to their structural relationships.

Second, to address the connectivity problem, we leverage WFC~\citeonline{Gumin2016wfc}, a procedural generation algorithm inspired by quantum mechanics. WFC generates coherent tile-based structures by propagating \emph{local constraints} across a \emph{grid} of \emph{cells}. In our approach, the tiles represent small segments of the paths connecting software entities. WFC generates these paths by selecting a tile for each cell and propagating the constraints imposed by neighboring tiles. By combining a sequence of compatible tiles, complete paths can be generated while respecting the required connections between software entities. Since constraints are defined at the \emph{tile} level (\ie specifying which elements can be placed in adjacent cells), WFC provides fine-grained control over the generated connections. This allows us to reduce visual clutter, such as overlapping lines, by restricting the set of possible tiles and adjusting their probabilities.

Furthermore, WFC is intrinsically non-deterministic. For a given software system, it can generate multiple different yet valid layouts, offering developers distinct perspectives of the same system. However, dependency relationships are inherently global constraints, while WFC operates locally. We devised our approach to generate valid and consistent paths (also good but not necessarily optimal without a cleanup step), as exemplified in \figref{fig:example_introduction}, while ensuring that the generated connections reflect the actual relationships in the system.

\section{Contributions}

The primary goal of this thesis is to investigate how Wave Function Collapse (WFC) can be adapted to generate software visualizations. The main contributions of this work are:

\begin{itemize}

    \item \textbf{A hybrid approach for software visualization:} We propose an approach that combines Multidimensional Scaling (MDS) for placing software classes with Wave Function Collapse (WFC) for generating the connections between them. 

    \item \textbf{A method for imposing global constraints using WFC local constraints:} We show how global connectivity constraints can be imposed using only the local constraints of WFC. This allows the algorithm to generate paths that connect only the intended classes, preventing connections between unrelated classes.

    \item \textbf{WFC tuning:} We present several extensions to adapt WFC to software visualization. These include multi-cell classes, maximum-entropy heuristic, directional path exits, dynamic tile weights, crossing avoidance, and backtracking strategies. Together, these changes make WFC suitable for our problem. 

    \item \textbf{Prototype implementation:} We implement the proposed approach in \wassis, a prototype developed in Pharo. \wassis provides the complete pipeline from source code analysis to class placement, WFC path generation, optional path optimization, and visualization. It also includes mechanisms for backtracking, memory management, and parallel execution to support the generation process.

    \item \textbf{Research paper:} Part of this work was published as a paper at VISSOFT 2026 in the NIER Track. This thesis extends that work with a more detailed description of the approach, additional WFC adaptations, implementation details, and an analysis of its characteristics and limitations.

\end{itemize}

\section{Document Structure}
The chapters of this thesis are organized as follows:

\begin{itemize}

    \item \textbf{Chapter 2 - State of the Art}. This chapter reviews software visualization techniques, such as graph-based, polymetric, 3D/VR, and cartographic approaches. It also introduces the main concepts of Wave Function Collapse (WFC) and its existing applications.

    \item \textbf{Chapter 3 - Approach}. This chapter presents the proposed approach, from the spatial layout of software systems using Multidimensional Scaling (MDS) to relationship merging and path generation using WFC. It also describes the main improvements introduced to handle larger systems.

    \item \textbf{Chapter 4 - Implementation}. This chapter describes the implementation of \wassis in Pharo. It covers code parsing, class placement, path exit assignment, max-heap optimization, dynamic tile weight, backtracking, path optimization and parallel execution.

    \item \textbf{Chapter 5 - Application}. This chapter shows how the proposed approach can be applied to software systems. It presents the generated visualizations and evaluates them using quantitative metrics.

    \item \textbf{Chapter 6 - Conclusion}. This chapter summarizes the main findings and contributions of this work. It also discusses the current limitations and possible future works.

\end{itemize}

\textbf{Appendix A} provides the mathematical derivation of the unnormalized Shannon entropy used during the WFC observation phase.
