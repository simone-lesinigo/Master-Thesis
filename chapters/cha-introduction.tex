As Thomas Ball stated:
\begin{quote}
    ``Software is intangible, having no physical shape or size.''~\citebibliography{Ball1996a}
\end{quote}

Unlike concrete objects, software has no shape that we can directly perceive. This raises a fundamental question: \emph{how can we represent something that has no physical form}? Software visualization addresses this question by mapping abstract software entities, such as classes, and their relationships onto visual representations that developers can explore. This thesis investigates how to place software entities and how to connect them, using Wave Function Collapse (WFC)~\citeonline{Gumin2016wfc}, a procedural content generation algorithm.

\section{Context and Motivation}
\label{sec:intro_motivation}

Program comprehension is older than software engineering itself: the term \emph{software engineering} was coined at the 1968 NATO conference in Garmisch~\citebibliography{Naur1969a}, but programmers had been reading and trying to understand code long before.

As software systems evolve and grow in complexity, developers spend a significant portion of their time reading, navigating, and mentally reconstructing code structures rather than writing new features. Understanding a codebase requires developers to build and maintain a mental model of the software, combining their existing programming and domain knowledge with information obtained from source code and related documentation~\citebibliography{Min2015a,Von1995a}. This process is not necessarily linear: developers may start from high-level goals and previous knowledge and move towards specific implementation details, or instead build their understanding bottom-up by gradually grouping low-level code structures into higher-level concepts. During this process, they continuously formulate hypotheses about the purpose and behavior of program components, check them against the available information, and update their mental model as their understanding improves.

Despite decades of improvements in integrated development environments (IDEs), new programming paradigms, and new programming languages, the amount of time developers spend trying to understand source code has remained surprisingly stable for over thirty years~\citebibliography{Sieg2016a}. In her review of program comprehension research, Siegmund discusses the models developed to explain how developers understand source code and highlights the renewed interest in human factors in software engineering, as well as the need for stronger empirical evidence on how developers perform their everyday tasks~\citebibliography{Sieg2016a}. Studies using techniques such as eye-tracking, electroencephalography (EEG), and functional magnetic resonance imaging (fMRI) further investigate the cognitive processes involved in code comprehension, showing that reading source code involves both language-processing and higher-level cognitive areas of the brain.

Empirical studies also highlight the practical consequences of this effort. LaToza \etal~\citebibliography{LaTo2006a} found that developers invest substantial effort in creating and maintaining mental models of software systems, while much of the rationale behind existing code remains undocumented. When source code and documentation do not provide enough information, developers often turn to their colleagues to understand past design decisions, historical changes, or temporary workarounds. These interactions can interrupt both their own work and that of their coworkers, reducing overall productivity. Similarly, Minelli \etal~\citebibliography{Min2015a} found that program comprehension accounts for roughly 70\% of developers' time, highlighting how much of software development involves understanding existing code rather than writing new code.

These challenges motivate the use of visual representations to support program comprehension. Visual modeling languages (\eg UML~\citebibliography{Andr2005a}) and software visualizations~\citebibliography{Agou2022a,Wett2007a,Kuhn2010a} represent software structures and relationships in ways that developers can explore without relying exclusively on source code. By making these structures more explicit, visualizations can help developers understand how software entities are organized and connected. However, producing useful visualizations of large software systems is itself challenging: entities must be positioned meaningfully, and their relationships must be represented without introducing excessive visual clutter.

\section{Problem Statement}
\label{sec-intro:problem_statement}
Applying software visualization to real-world, large-scale systems introduces two fundamental and interconnected challenges:

\begin{itemize}
    \item \textbf{The Layout Problem:} Given a set of software entities, one must decide how to position them meaningfully in the visual representation. Different layouts can highlight different structural or semantic aspects of the software, such as inheritance relationships or package structure. A poor layout can hide important patterns and make the overall structure of the system harder to understand.
    
    \item \textbf{The Connectivity Problem:} While displaying relationships (\eg, inheritance, method calls, and dependencies)  enriches the information about the system, large software graphs often become excessively dense. As the entity number increases, connections scale rapidly, leading to visual clutter, edge crossings, and unintelligible diagrams.
\end{itemize}

\section{Proposed Approach}
In this thesis, we explore a novel approach designed to tackle both problems. The approach is implemented in \wassis, a tool developed in Pharo that combines Multidimensional Scaling (MDS) for class placement with Wave Function Collapse for path generation. This combination aims to produce layouts that are both structurally informative and easy to interpret.

First, we use Multidimensional Scaling~\citebibliography{Torg1952a,Doug1998a}, a dimensionality reduction technique, to establish the placement of software entities on the canvas according to their structural relationships, aiming to position related entities closer to each other.

Second, to address the connectivity problem, we leverage WFC~\citeonline{Gumin2016wfc}, a procedural generation algorithm inspired by quantum mechanics. WFC generates coherent tile-based structures by propagating \emph{local constraints} across a \emph{grid} of \emph{cells}. In our approach, the tiles represent small segments of the paths connecting software entities. WFC generates these paths by selecting a tile for each cell and propagating the constraints imposed by neighboring tiles. By combining a sequence of compatible tiles, complete paths can be generated while respecting the required connections between software entities. Since constraints are defined at the \emph{tile} level (\ie specifying which elements can be placed in adjacent cells), WFC provides fine-grained control over the generated connections. This allows us to reduce visual clutter, such as overlapping lines, by restricting the set of possible tiles and adjusting their probabilities.

Furthermore, WFC is intrinsically non-deterministic. For a given software system, it can generate multiple different yet valid layouts, offering developers distinct perspectives of the same system. However, dependency relationships are inherently global constraints, while WFC operates locally. We devised our approach to generate valid and consistent paths (also good but not necessarily optimal without a cleanup step), as exemplified in \figref{fig:example_introduction}, while ensuring that the generated connections reflect the actual relationships in the system.

\section{Contributions}

The primary goal of this thesis is to investigate how Wave Function Collapse can be adapted to generate software visualizations. The main contributions of this work are:

\begin{itemize}

    \item \textbf{Combining MDS with WFC:} We combine Multidimensional Scaling to position software classes according to their structural relationships with Wave Function Collapse to generate paths connecting the intended classes. This separates class placement from path generation while integrating both into a single visualization pipeline.

    \item \textbf{A method for imposing global constraints using WFC local constraints:} We show how global connectivity constraints can be imposed using only the local constraints of WFC. This allows the algorithm to generate paths that connect only the intended classes, preventing connections between unrelated classes and preserving the intended dependency relationships throughout the visualization.

    \item \textbf{Adapting WFC to software visualization::} We present several extensions to adapt WFC to software visualization. These include multi-cell classes, maximum-entropy heuristic, directional path exits, dynamic tile weights, crossing avoidance, and backtracking strategies. Together, these changes make WFC suitable for the layout and the connectivity problem. 

    \item \textbf{Tool implementation:} We implement the proposed approach in \wassis, a tool developed in Pharo. \wassis provides the complete pipeline from source code analysis to class placement, WFC path generation, optional path optimization, and visualization. It also includes mechanisms for backtracking, memory management, and parallel execution to support and optimize an efficient generation process.

\end{itemize}

\section{Document Structure}
The thesis is organized as follows:

\begin{itemize}

    \item \textbf{Chapter 2 - State of the Art}. This chapter reviews software visualization techniques, such as graph-based, polymetric, 3D/VR, and cartographic approaches. It also introduces the main concepts of Wave Function Collapse and its existing applications.

    \item \textbf{Chapter 3 - From Code to Visualization}. This chapter presents the proposed approach, from the spatial layout of software systems using Multidimensional Scaling to relationship merging and path generation using WFC. It also describes the main improvements introduced to handle larger systems.

    \item \textbf{Chapter 4 - Implementation}. This chapter describes the implementation of \wassis in Pharo. It covers code parsing, class placement, path exit assignment, max-heap optimization, dynamic tile weight, backtracking, path optimization and parallel execution.

    \item \textbf{Chapter 5 - Experiments and Results}. This chapter evaluates \wassis on selected software systems. It compares the generated visualizations and investigates how different configurations affect the ability to find valid solutions and the time required for generation.

    \item \textbf{Chapter 6 - Conclusion}. This chapter summarizes the main findings and contributions of this work. It also discusses the current limitations and possible future works.

\end{itemize}

\textbf{Appendix A} provides the mathematical derivation of the unnormalized Shannon entropy used during the WFC observation phase.
